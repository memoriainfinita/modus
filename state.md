# Modus — state

What is true now. What already happened lives in `state-history.md`.

## Project

**Modus** — see and understand the harmony of what you play, in real time. Aimed at being a complete, professional, useful, universal and didactic app, for studying, transcribing songs, composing, teaching and making videos. No time or budget limits, no marketing or profit goals. GPL-3.0, part of the **memoriainfinita** ecosystem: UMT (developed for Modus, all theory) and notae (diagrams).

- **Spec:** `docs/spec.md` (purpose, design, behaviour) · **UMT contract:** `docs/umt-contract.md` · Executed plans and earlier spec revisions in `.archive/` (local, gitignored)
- **Stack and commands:** `README.md`. Not there: pnpm 11 needs `allowBuilds: esbuild: true` in `pnpm-workspace.yaml` (it blocks install scripts by default); TypeScript held on 5.x on purpose; UMT pinned to the tag `v0.12.0`, notae to `5ba68c2` (the isomorphic hex grid; 2026-10-27; before it `5a3ae1b`, per-dot colours and labels), both served from `vendor/`

## Patterns

- [language] Everything in English: code, comments, documentation (spec, README, state.md), commit messages. Confirmed 2026-05.
- [typescript] esbuild watch mode, same toolchain as UMT and notae. Confirmed 2026-05.
- [typescript] `pnpm build` does not typecheck (esbuild). Use `pnpm exec tsc --noEmit`. Confirmed 2026-05.
- [build] `dist/` is tracked in git, same as notae and UMT. Commit it in sync with `src/`. Confirmed 2026-05.
- [build] pnpm, not npm. Confirmed 2026-10.
- [deps] UMT pinned to a release tag (`v0.12.0`) in `package.json` and `scripts/vendor.mjs`, notae to a commit hash there; never `@main`/`@master`. The page loads them from `vendor/` (tracked): after a bump, `pnpm vendor`, then the tests. Bump deliberately, reading UMT's `CHANGELOG.md`. Confirmed 2026-10.
- [naming] Project name: Modus (Latin — mode, measure). Confirmed 2026-05.
- [theory] Music-theory fixes go into UMT or notae, then Modus bumps the pin. No workarounds in Modus for library output. Since 2026-10-10 only the session running the UMT audit (`umt/docs/auditoria-2026-10.md`) commits to UMT: Modus writes what it needs in `umt/docs/notas-desde-modus-2026-10.md` (both local, gitignored) and waits. Confirmed 2026-10.
- [ux] The look (redesign 2026-10-12): neutral black (#141414, panels #1d1d1d) and one accent, parchment #d9c9a3, for what is on, focus, terms and cadences; the indigo and the blue-tinted ground are gone. One colour code for harmony, the function (`--fn-t/s/d`, `functionColor` in `theory/chord.ts`): chord header, piano keys, circle, key-panel chips, history and view windows; quality is read in the name, a chord without a function is drawn in `--chord-none`. The light, contrast and paper themes follow the same tokens. Confirmed 2026-10.
- [ux] The bar (2026-10-26): key, field for a chord or an order (`ui/commands.ts`), input status (computer keyboard and mic icons while on), sound status, the page (layout, presentation, view windows), Settings, Help; each control once, no rail. On a phone the page goes to the bottom bar; below 1000 px the brand's name, the playing mode and the / hint hide. No native select in view: a list of buttons stands for each, the select hidden as the holder of the value. Confirmed 2026-10.
- [ux] Quiet controls: a panel's options go in the ⋯ menu of its header (`panelMenu` in `ui/layout.ts`), not on view; panels have no border, 10 px apart; line icons (`ui/icons.ts`). The chord is a header across the page in Standard, its name sized by the panel's height and shrunk to its width (`fitChordName`, after each chord and on resize: a tall narrow panel or full screen carried C7#9b13 past the edge); Velocity is left to the layout menu. The chord's header and the diagrams' (staff, circle, piano, velocity) float over the panel, seen on hover or focus (2026-10-26, asked by the user); panels whose text or controls start at the top keep theirs in place, where a floating one would cover them; on touch and on a phone all stay. Type: chord 64, numeral 30, panel title 15, values 13–14 (Analysis 13, key panel 12 by default, so each shows all it showed before the redesign), labels 12. Checked 2026-10-12 against the version before, per layout: no panel hides more than it did. Confirmed 2026-10.
- [layout] The stored layout keeps each panel's full height; what is drawn is `fitGrid` (`layout/grid.ts`) over the rows each fitted panel's content needs (`FITTED`, `measureContentRows` in `ui/layout.ts`, re-measured on a timer after any change in its body, not on a frame: a page out of sight gets none). On a phone (≤ 720 px) nothing is fitted: each panel keeps its rows in the layout and text that does not fit scrolls inside it; the chord, first on the page, keeps its height auto. A panel that grew with a chord pushed the piano from under the fingers (2026-10-26). While a panel is dragged and while presenting, the layout is drawn at its own sizes. Confirmed 2026-10.
- [settings] Settings › Panels and Windows are drawn from the ⋯ menus and the views menu (`renderMirrors` in `ui/settings.ts`): a group of chips is a choice, an item with `aria-pressed` a switch, a row of − + its steps; a change clicks the menu's own control and the rows are drawn again. A new ⋯ option shows in Settings by itself if it follows those forms; prefs.ts preferences, `.menu-action` and exports are left out. Confirmed 2026-10.
- [ux] Destructive actions run at once and offer Undo (`ui/undo.ts`), never a confirmation. Confirmed 2026-10.
- [ux] Play on single click. A double click is detected by hand (same target within 400 ms) wherever the element is rebuilt on click: a rebuilt node never gets the browser's dblclick. Confirmed 2026-10.
- [audio] Stay on soundfont-player 0.12.0 + FluidR3_GM: archived upstream but pinned and working. smplr (same author) loads its GM soundfonts from the same `gleitz.github.io`, so swapping does not remove the sample-host risk. A reason to move would be smplr's sampled instruments (Steinway with velocity layers, electric pianos) or reverb, not maintenance. Confirmed 2026-10.
- [spelling] Display spelling goes through `theory/spelling.ts` over UMT's `spellPitchInKey` / `spellChord` / `spellChordInKey`: MIDI detections are written in the analysis key and rewritten on a key change; without a key a chord's notes are written by the chord (F# in D, Cb in Abm), single notes and intervals keep MIDI's flats; the Neck view labels each dot with the spelled name (E# in F# major), not notae's flat or sharp preference; a chord picked from history, song or CoF keeps its symbol and its notes are named by interval; history chips render in the current key. Note names may carry any accidentals (`notes.ts`: F##4, B#3 = MIDI 60). Confirmed 2026-10.
- [testing] While iterating, only the e2e checks of what changed: `E2E_ONLY="text" pnpm test:e2e` runs the checks whose name holds it (~20 s); the whole walk (~8 min) before a commit the user reviews. A Playwright action fails after 10 s, not 30. Confirmed 2026-10.
- [testing] Unit tests run in Node; a file that needs a DOM (diagrams, theme tokens, storage, Settings) starts with `// @vitest-environment jsdom`. `tests/setup-umt.ts` puts UMT on `globalThis` and, without a DOM, gives Node's navigator English (Node reports the system's language). 406 tests in ~28 s, was ~78 s. Confirmed 2026-10.
- [testing] `pnpm test:e2e` after each behaviour change: `tests/e2e/smoke.mjs` serves the repo, opens the installed Chrome (`channel: 'chrome'`) with a fake `navigator.requestMIDIAccess`, and plays notes through `window.__midi`. Each check releases all notes when it ends. `window.__plug(id, name|null)` hot-plugs; `__hotplug(false)` switches to Firefox behaviour. Confirmed 2026-10.
- [testing] `pnpm test:e2e:midi` (`tests/e2e/real-midi.mjs`) for the real Web MIDI path: Node writes to "loopMIDI Port" with `jzz`; Chrome gets `grantPermissions(['midi'])`; Playwright's Firefox gets a fresh profile whose `permissions.sqlite` holds the `midi` rows the site-permission add-on would write (no pref skips the add-on; Playwright knows no `midi` permission for Firefox). Needs loopMIDI running. Browsers launch muted (`--mute-audio`, `media.volume_scale` 0). Hot-plug stays in the fake: loopMIDI's GUI cannot unplug a port. Confirmed 2026-10.
- [testing] Every e2e browser context pins English (`locale: 'en-US'`, Firefox `intl.accept_languages`): Modus follows the browser's language, and Chrome without a locale takes the system's, Spanish on this machine. The Spanish checks switch from the ? panel. Confirmed 2026-10.
- [a11y] A `title` on a focusable element reaches a screen reader as its description: a mouse tooltip goes on a child that is not focused, or gets a keyboard `aria-description` over it. An empty `aria-description` does not hide the `title` in Firefox. A focusable element named by `aria-label` needs a role that takes a name (a generic `<header>` gets none in Firefox). A `role="img"` named by its label still gives NVDA its text in Firefox: the drawing inside is `aria-hidden` (staff, piano, isomorphic, in `renderZone1Diagrams`). Check with NVDA in Firefox, not only Chrome's accessibility tree. Confirmed 2026-10.
- [view] View windows are the same page with `?view=`: `app.ts` runs `runViewerFromUrl()` instead of `init()`, so a view never opens MIDI or audio. They get the detector state over the `modus-view` BroadcastChannel (`view/channel.ts`); anything a view should follow must go through `publishView()` in `app.ts`. Confirmed 2026-10.
- [view] Layout windows are the same page with `?window=<preset or saved:name>&bg=`: `initLayoutWindow` instead of `init()`, no MIDI, audio or microphone, storage read-only (`setStorageReadOnly`: `save()` and the song library write nothing, so the main window's layout and songs stay its own). The main window sends `mirrorState()` over the `modus-mirror` BroadcastChannel (`view/mirror.ts`), once per task, from `renderDetector`, `onHistoryChange`, `renderZone3` and the song's playing step; `applyMirror` sets it and draws with the same functions. State a panel draws from must be in `MirrorState`. Preferences reach it by reloading on a `storage` event. Confirmed 2026-10.
- [midi] Firefox reports no hot-plug (no statechange, `inputs` frozen) but a new `requestMIDIAccess` returns the current ports: `input/midi.ts` rescans every 2 s while visible and on focus. The device the user picked (or the first used) is preferred, found by name (Chrome ids are positional, `input-0`; Firefox ids are stable hashes): a fallback never replaces it. Confirmed 2026-10.

## Preferences

- `pnpm dev` only when a task needs continuous rebuilds, not at session start; otherwise `pnpm build`. When launched: in background (`run_in_background: true`, `timeout: 7200000` — the default background limit kills it after 30 min), never with `!` in chat (it blocks). `--watch=forever` outlives TaskStop and the session: at the end, kill the `cmd.exe` tree whose command line has `watch=forever` (`taskkill /PID <pid> /T /F`).
